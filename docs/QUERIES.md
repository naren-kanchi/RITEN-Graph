### Top trade links with shares

Uses: CTE, JOIN, GROUP BY, ORDER BY, SUM, RANK and SUM window functions. Served by `GET /reports/top-links`.

```sql
WITH links AS (
    SELECT exporter_actor_code, importer_actor_code, SUM(trade_value_usd_millions) AS value, COUNT(*) AS observations
    FROM trade_flow WHERE year = 2023 GROUP BY 1, 2)
SELECT RANK() OVER (ORDER BY value DESC) AS rank, exporter_actor_code, importer_actor_code, value,
       ROUND(100 * value / SUM(value) OVER (), 2) AS share_of_year_pct,
       ROUND(100 * value / SUM(value) OVER (PARTITION BY exporter_actor_code), 2) AS share_of_exporter_pct
FROM links ORDER BY rank LIMIT 5
```

### Actors restricting each other

Uses: CTE, self-join. Served by `GET /reports/mutual-restrictions`.

```sql
WITH pair AS (
    SELECT imposing_actor_code AS a, target_actor_code AS b, COUNT(*) AS n FROM restriction_measure GROUP BY 1, 2)
SELECT x.a AS actor_a, y.a AS actor_b, x.n AS a_on_b, y.n AS b_on_a
FROM pair x JOIN pair y ON x.a = y.b AND x.b = y.a WHERE x.a < y.a ORDER BY x.n + y.n DESC LIMIT 5
```

## Do the indexes help?

Each query is measured with its index, then with the index dropped inside a transaction that is rolled back. These tables are small, so absolute savings are modest. Where the planner still prefers a sequential scan, that is reported as it happened.

| Query | Index | Plan with | Time with | Buffers with | Plan without | Time without | Buffers without |
|---|---|---|---|---|---|---|---|
| Trade between one directed pair in one year | `trade_pair_year_idx` | index trade_pair_year_idx | 0.220 ms | shared hit=2 | index trade_flow_grain_uq | 0.642 ms | shared hit=8 |
| Full-text search | `restriction_search_idx` | index restriction_search_idx | 0.327 ms | shared hit=56 | sequential scan | 0.600 ms | shared hit=200 |
| Rows under export control (partial index) | `trade_controlled_idx` | index trade_controlled_idx | 0.200 ms | shared hit=2 | index trade_period_idx | 0.496 ms | shared hit=127 |
| Measures against one target | `restriction_target_date_idx` | index restriction_target_date_idx | 0.162 ms | shared hit=3 | sequential scan | 0.366 ms | shared hit=200 |

## Cypher

### Direct trade partners

Uses: Parameterized match on the yearly summary edge. Served by `GET /graph/neighborhood/{code}`.

```cypher
MATCH (a:Actor {actor_code: $code})-[r:TRADE_SUMMARY {year: $year}]-(p:Actor)
RETURN p.actor_code, r.value ORDER BY r.value DESC
```

### Restrictions on or by an actor

Uses: Aggregation in Cypher. Served by `GET /graph/neighborhood/{code}`.

```cypher
MATCH (a:Actor {actor_code: $code})-[r:IMPOSED]-(p:Actor) WHERE r.year = $year
RETURN p.actor_code, count(r) AS measures, max(r.severity) AS max_severity
```

### Bounded multi-hop paths

Uses: Variable-length traversal, simple paths only, weakest hop via reduce(). Served by `GET /graph/paths`.

```cypher
MATCH p = (s:Actor {actor_code: $source})-[:TRADE_SUMMARY*1..3]->(t:Actor {actor_code: $target})
WHERE all(r IN relationships(p) WHERE r.year = $year)
  AND all(i IN range(0, length(p) - 1) WHERE NOT nodes(p)[i] IN nodes(p)[i + 1..])
RETURN [n IN nodes(p) | n.actor_code] AS route,
       reduce(m = 1e15, r IN relationships(p) | CASE WHEN r.value < m THEN r.value ELSE m END) AS bottleneck
ORDER BY bottleneck DESC LIMIT 25
```

### Routes through an intermediary

Uses: Pattern plus COUNT subqueries that check restrictions on each hop. Served by `GET /graph/reroutes`.

```cypher
MATCH (s:Actor {actor_code: $source})-[a:TRADE_SUMMARY {year: $year}]->(v:Actor)-[b:TRADE_SUMMARY {year: $year}]->(t:Actor {actor_code: $target})
WITH s, t, v, a, b,
     COUNT { (s)-[x:IMPOSED]-(v) WHERE x.year <= $year } AS first_hop,
     COUNT { (v)-[x:IMPOSED]-(t) WHERE x.year <= $year } AS second_hop
RETURN v.actor_code, first_hop, second_hop, first_hop + second_hop = 0 AS unrestricted
```

### Position in the network

Uses: Whole-graph aggregation: weighted degree and broker paths. Served by `GET /graph/network`.

```cypher
MATCH (a:Actor)
OPTIONAL MATCH (a)-[o:TRADE_SUMMARY {year: $year}]->()
WITH a, sum(o.value) AS exports, count(o) AS export_partners
RETURN a.actor_code, exports, export_partners,
  COUNT { ()-[x:TRADE_SUMMARY {year: $year}]->(a)-[y:TRADE_SUMMARY {year: $year}]->() WHERE startNode(x) <> endNode(y) } AS broker_paths
```

### Headquartered companies

Uses: One-hop identity lookup. Served by `GET /graph/neighborhood/{code}`.

```cypher
MATCH (c:Company)-[:HEADQUARTERED_IN]->(:Actor {actor_code: $code})
RETURN c.company_key, c.name, c.domain ORDER BY c.name
```
